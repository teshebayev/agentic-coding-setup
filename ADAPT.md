# Задание агенту: перенести агентный сетап в этот репозиторий

Ты — Claude Code в чужом репозитории. Рядом лежит архив агентного сетапа проекта «DWH-аналитик» (Python-харнесс
над хранилищем данных). Твоя задача — перенести сетап в текущий репозиторий и адаптировать под него. Копировать
файлы вслепую нельзя: половина содержимого — про чужой домен.

Структура архива:

- `setup/` — файлы сетапа ровно в тех путях, где они лежат в корне репозитория (включая скрытые `.claude/`,
  `.superpowers/`, `.mcp.json`, `.gitignore`).
- `instructions/<путь>.md` — инструкция к каждому файлу из `setup/`: что это, когда подхватывается, что в нём у
  нас, что должно быть у вас, шаги адаптации, связи. **Перед тем как трогать файл — прочитай его инструкцию.**
- `examples/` — образец полного изменения OpenSpec (proposal, specs, design, tasks). В `openspec/` не копируется.

Метки действий в инструкциях: **оставить как есть**, **подстроить**, **переписать**, **заменить своим или
удалить**, **не править руками** (генерирует OpenSpec CLI), **не править** (сторонний MIT-скилл).

## Шаг 0. Прочитай

`README.md` архива, этот файл, все инструкции из `instructions/` (они короткие). Если в целевом репозитории уже
есть `CLAUDE.md`, `AGENTS.md`, `.claude/` или `openspec/` — прочитай их тоже: существующее не затираешь, а сливаешь.

## Шаг 1. Разведка (сам, без вопросов пользователю)

Собери факты и запиши их себе списком:

- язык и стек, менеджер пакетов, точки входа;
- команды: установка, все тесты, один тест, линт/типы, локальный запуск. **Запусти** тесты и линт, замерь время;
- структура модулей, есть ли README в модулях, где документация, как оформлены коммиты (`git log --oneline -20`);
- где секреты: `.env*`, ключи, `credentials*`, `secrets/`, kubeconfig — что из этого в `.gitignore`;
- что опасно запускать: деплой, миграции, прод/стенд, платные API (Makefile, `package.json`, CI, docker-compose);
- крупнейшие файлы, самые частые фиксы (`git log --oneline | grep -iE 'fix|исправ' | head -30`);
- установлены ли `jq`, `git`, `sha1sum`, `timeout`, Node ≥ 20 (для OpenSpec).

## Шаг 2. Один раунд вопросов пользователю

Задай пронумерованные вопросы, к каждому — твой рекомендованный ответ (на основе разведки), чтобы «да» его
принимало:

1. Язык документации, комментариев, коммитов и артефактов OpenSpec.
2. Берём ли процесс OpenSpec (`/opsx:*`) и superpowers — или только правила, хуки и скиллы.
3. Что агенту **никогда** нельзя, что — **только с разрешения**, что — свободно (предложи списки).
4. 3–7 главных инвариантов архитектуры: «что сломает новичок, если не знает».
5. Самые хрупкие области кода — под них будут доменные правила, 0–2 ревьюера-субагента, 2–4 скилла-процедуры.
6. MCP-серверы, которые можно делить с командой (или никаких).
7. Категории NFR для proposal (предложи 3–5) и нужна ли «матрица окружений».

Дальше работай по ответам; новые вопросы — только если всплыло неразрешимое.

## Шаг 3. Перенос — в этом порядке

Правила работы:

- Перед каждым файлом — его инструкция из `instructions/`. После — пройди её раздел «Связи» и поправь ссылки.
- Пиши на языке, выбранном в шаге 2. Наши файлы на русском, а `CLAUDE.md` — на английском; сохрани эту схему
  или выбери другую с пользователем.
- Не переноси наше доменное содержимое: харнесс, DWH, replay, плейбуки, витрины, LibreChat, MCP-сервер
  `dwh-analyst`, Ташкент, `uv run pytest` (если стек другой).
- Не коммить, пока пользователь не попросит.

## Шаг 4. Проверка

1. **Остатки чужого домена** — должно быть пусто или осознанно:
   `grep -rniE 'dwh|harness|replay|playbook|плейбук|librechat|tashkent|marts|витрин|dwh_analyst_mcp|alembic' CLAUDE.md .claude scripts/agent openspec/config.yaml docs GLOSSARY.md .mcp.json`
   (исключение — сгенерированные `openspec-*` и вендоренные скиллы).
2. **Ссылки:** каждый путь, упомянутый в `CLAUDE.md`, правилах, скиллах и командах, существует.
3. **`paths:` правил** находят файлы: `git ls-files '<glob>'` для каждого.
4. **Хуки:** дымовые тесты из инструкций к `guard.sh`, `post-edit.sh`, `stop-tests.sh`; `bash -n scripts/agent/*.sh`.
5. **OpenSpec:** `openspec validate --all` (или `openspec list`) отрабатывает без ошибок на пустом проекте.
6. **Тесты и линт проекта** зелёные (сетап не должен ничего сломать).
7. Попроси пользователя перезапустить Claude Code и открыть `/hooks`, `/memory` (видно правила), набрать `/` (видны
   `/opsx:*`, `/grill-with-docs`, свои команды).

## Шаг 5. Отчёт

открытыми, вывод проверок шага 4, и что пользователю сделать руками (установить superpowers, перезапустить сессию,
закоммитить).
