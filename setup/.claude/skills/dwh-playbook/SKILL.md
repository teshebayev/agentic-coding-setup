# Плейбук DWH

Формат — `dwh-knowledge/playbooks/README.md` (читай целиком перед работой); правила —
`.claude/rules/knowledge.md`.

## Шаги

1. **Черновик — вне `playbooks/`.** Любая папка `playbooks/<имя>/SKILL.md` сразу видна модели в проде.
   Пока плейбук не готов, держи его в `openspec/changes/<change>/draft-playbook/<имя>/`.
2. **Таблицы и колонки** — по карточкам `dwh-knowledge/schemas/<домен>/*.md`, ловушки — `traps.md`. Если
   подключён MCP-сервер `dwh-analyst` (демо, `.mcp.json`), проверяй SQL его `validate_sql`; живой DWH
   этим сервером не трогается.
3. **SKILL.md**: `name` = имя папки, одна строка `description` (идёт в индекс промпта — коротко, это NFR-C),
   `domains` (иначе плейбук видят только пользователи без ограничений), `triggers`, `params` с типами
   (`date`, `uuid`, `uuids`, `strs`, `int`, `str`), `blocks`. Разделы «Как считать», «Ловушки», «Пример».
4. **Шаблоны `*.sql.j2`**: параметры подставляются готовыми литералами — кавычек вокруг `{{ … }}` не пиши;
   периоды — полуинтервалы `>= date_from AND < date_to`.
5. **tests.yml**: ожидаемые числа на закрытом периоде (или форма выдачи для срезов «сейчас») с комментарием,
   откуда числа и когда сверены.
6. **Проверка.** Офлайн — `uv run pytest -q dwh-analyst-mcp/tests`. На живом DWH —
   `uv run pytest eval -m live -k <имя>` **только с разрешения пользователя** (хук спросит).
7. **Перенос** в `dwh-knowledge/playbooks/<имя>/` — последним шагом, после зелёной проверки; запись в
   `dwh-knowledge/STATUS.md`.
