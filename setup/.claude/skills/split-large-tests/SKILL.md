# Разбиение большого файла тестов

Это перенос, а не переписывание: имена тестов и их логика не меняются.

1. **Снимок до.** `uv run pytest --collect-only -q <файл> | tail -1` — число тестов; сохрани список
   `--collect-only -q` во временный файл в scratchpad.
2. **План.** Сгруппируй тесты по смыслу (тестируемый плагин, сценарий, класс), не по числу строк. Цель —
   100–200 строк на файл; связанную группу не рви ради лимита. Покажи план: новые файлы, сколько тестов в
   каждом, что уходит в общий код.
3. **Общий код.** Фикстуры, нужные нескольким файлам, — в `conftest.py` той же папки (или выше), а не копией
   в каждый файл. Помощники-функции — в модуль `tests/_<тема>_helpers.py` с импортом. `monkeypatch` и
   фикстуры со scope действуют по файлу — проверь, что каждый новый файл получает нужные.
4. **Перенос.** Имена файлов — `test_<тема>_<подтема>.py`; исходный файл удаляется только когда всё перенесено.
5. **Снимок после.** Тот же `--collect-only`: множество имён тестов (без префикса файла) совпадает с
   исходным. Затем `uv run pytest -q` целиком и `uv run ruff check tests/`.
6. Итог: таблица «файл — тестов — строк», совпадение до/после.
