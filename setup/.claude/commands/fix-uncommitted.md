# Разбор незакоммиченных файлов

1. Запусти `scripts/agent/uncommitted-files.sh`, прочитай `uncommitted-files.md`; бери только `[ ]`.
2. Для каждого файла по очереди запусти **один** субагент (Agent, `general-purpose`, не в фоне) и дождись
   его, прежде чем запускать следующий. Промпт субагенту:

   > Проверь `<путь>` в репозитории DWH-аналитик. Не делай git commit. До трёх циклов «проверка → правка»:
   > 1. Диагностика: `mcp__claude-vscode__getDiagnostics` для файла (если инструмент недоступен — пропусти)
   >    и, для `.py`, `uv run ruff check <путь>`. Выпиши **каждое** замечание: `[уровень] строка N: текст`.
   >    Нет замечаний — так и напиши.
   > 2. Исправь ошибки и предупреждения. Не трогай поведение без теста (`.claude/rules/tdd-workflow.md`).
   > 3. Дубли: функции и константы этого файла, определённые ещё где-то (`grep -rn "def <имя>\|<ИМЯ> ="`), —
   >    оставь одно определение в подходящем общем модуле, остальное — импорт. Не объединяй код через
   >    границу `harness/` ↔ `dwh_analyst_mcp` (`.claude/rules/mcp-boundary.md`).
   > 4. Неиспользуемые импорты и переменные — удаляй, только убедившись поиском, что они не нужны (в том числе
   >    фикстуры pytest, которые используются по имени параметра).
   > 5. Повтори диагностику.
   > Ответ строго в формате:
   > **Найдено**: N (список) · **Исправлено**: N · **Оставлено**: N (с причиной) · **Изменённые файлы**: …

   Документацию и `.md`-файлы субагент проверяет только на битые ссылки на файлы.
3. После каждого субагента отметь файл `[x]` в `uncommitted-files.md` и запиши одну строку итога.
4. В конце по очереди: `uv run ruff check .`, `uv run pytest -q`, offline-демо
   (`uv run python -m harness.cli --layers base.yml,dwh.yml,demo.yml ask "Сколько отгрузок по KOTON за прошлую неделю?"`).
   Падение — исправь и повтори.
5. Итог: сколько файлов, сколько с правками, что оставлено и почему, статус трёх проверок.
