Вариант `/opsx:apply` для больших изменений: основной контекст держит только план и прогресс, а каждая задача
делается в свежем субагенте — так контекст не забивается кодом прошлых задач.

**Вход**: `$ARGUMENTS` — имя изменения (как у `/opsx:apply`).

## Порядок

1. Выполни шаги 1–5 скилла `openspec-apply-change` (выбор изменения, статус, `openspec instructions apply`,
   чтение context-файлов, показ прогресса). Сам код в основном контексте не пиши.
2. Для каждой невыполненной задачи из tasks.md, по порядку:
   - Запусти **один** субагент (Agent, `general-purpose`, не в фоне). В промпт передай: путь к изменению,
     текст задачи с её FR/NFR, пути context-файлов (proposal, specs, design, tasks) и затронутые модули.
     Обязательно добавь: «Не делай git commit. Сделай только эту задачу. Перед завершением прогони
     `uv run pytest -q` и пришли хвост вывода. Если требование неясно или нужен живой DWH — остановись и
     опиши блокер».
   - Дождись результата. Следующий субагент не запускай, пока не вернулся текущий; параллельно — никогда.
   - Успех → отметь задачу `- [ ]` → `- [x]` в tasks.md и запиши одну строку итога.
   - Блокер, неясность или красные тесты → остановись и спроси пользователя.
3. В конце — `uv run ruff check .` и `uv run pytest -q`. Если задеты `harness/core` или `harness/context` —
   субагент `replay-reviewer`. Итог: сколько задач сделано, что осталось, вывод тестов.

Коммиты делает пользователь.
