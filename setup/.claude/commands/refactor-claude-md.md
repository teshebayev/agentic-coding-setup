# Аудит CLAUDE.md

CLAUDE.md грузится в каждую сессию целиком: каждая строка стоит токенов всегда и отнимает внимание у
остальных. Задача — сделать файл короче и точнее, ничего не потеряв.

**Аргументы** (`$ARGUMENTS`): путь (по умолчанию `./CLAUDE.md`) и флаг `--apply`. Без `--apply` ничего не
записывай — только отчёт. Первой строкой ответа назови режим и путь.

## Шаги

1. Прочитай CLAUDE.md, список `.claude/rules/` (с `paths:`), `.claude/skills/`, `.claude/settings.json`
   (хуки), `docs/README.md`.
2. Для каждого абзаца или пункта задай вопрос: **«если убрать, Claude начнёт ошибаться в этом проекте?»**
   - нет или не уверен → удалить;
   - да, но касается одной области кода → правило в `.claude/rules/` с `paths:`;
   - да, это процедура «как сделать X» → скилл;
   - да, и нарушение можно поймать скриптом → хук (и короткая строка в CLAUDE.md, если нужна причина);
   - да, длинная справка → документ в `docs/` или README модуля, из CLAUDE.md — ссылка;
   - да, и касается каждой сессии → оставить, сократив.
3. Убери то, что Claude и так видит: содержимое `pyproject.toml`, дерево файлов, общие правила Python.
4. Проверь, что ничего не дублируется между CLAUDE.md и правилами и что каждое правило из таблицы
   CLAUDE.md существует.

## Отчёт

Таблица: «фрагмент → решение (оставить / сократить / перенести в X / удалить) → почему». Затем — новый
текст CLAUDE.md целиком и список файлов, которые будут созданы или изменены, с итоговым числом строк
«было → стало».

С `--apply`: запиши изменения и покажи `git diff --stat`. Не коммить.
