# Правило: трассируемость требований

Любой артефакт изменения OpenSpec ссылается на ID требования из его `proposal.md`. Нет ссылки — артефакт
либо лишний, либо ссылку забыли.

## ID (уникальны в пределах изменения)

`G1…` цели · `NG1…` не-цели · `FR1…` функциональные · `NFR-S1…` безопасность · `NFR-RP1…` совместимость replay ·
`NFR-C1…` стоимость · `NFR-P1…` производительность · `M1…` метрики · `Q1…` открытые вопросы.
`add-x.FR1` и `fix-y.FR1` — разные требования.

## Куда ставить ссылку

| Артефакт | Ссылка |
|---|---|
| Инвариант или сценарий дельта-спеки | `# реализует FRn из <change>` |
| Задача в tasks.md | `(FR2, NFR-S1)` в конце строки |
| Новый плагин, функция, класс | строка в docstring: `Реализует FR2 из <change>.` |
| Тест pytest | комментарий над тестом: `# FR2: <что проверяем>` |
| Плейбук | `# FR2` в комментарии к кейсу в `tests.yml` |
| design.md | «Контекст: из-за FR2 …» |

Не размечай задним числом код, который изменение не трогает.

## Проверка перед архивом

Для каждого FR/NFR из proposal найдётся хотя бы одна реализация и один тест:
`grep -rn "FR2" harness dwh-analyst-mcp tests dwh-knowledge`.
