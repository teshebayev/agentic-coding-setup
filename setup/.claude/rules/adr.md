# Правило: ADR

ADR — долгоживущее решение, не привязанное к одному изменению. Пишется, только если верны все три:
1. **трудно отменить** — передумать потом дорого;
2. **удивляет без контекста** — читатель кода спросит «почему так?»;
3. **результат компромисса** — были реальные альтернативы.

Файл `docs/adr/NNNN-kebab-case.md`, номер — следующий за максимальным. Формат — как в
`.claude/skills/domain-modeling/ADR-FORMAT.md`, но по-русски:

```markdown
---
status: accepted   # proposed | accepted | deprecated | superseded by ADR-NNNN
---
# <Короткое название решения>

<1–3 предложения: контекст, что решили, почему.>
```

Разделы «Рассмотренные варианты» и «Последствия» — только если реально полезны.
Принятый ADR не переписываем: новое решение — новый ADR, у старого `superseded by ADR-NNNN`.
Кандидаты из уже сделанного: event log как источник истины, DWH только через MCP, ручные миграции без ORM.
