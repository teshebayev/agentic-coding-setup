# Правило: TDD — красный, зелёный, рефакторинг

Для логики харнесса и MCP-сервера: плагины, хуки, валидатор, сборка промпта, хранилище, API.

## Когда TDD не нужен

Установка и настройка инструментов, конфиги и docker, документация, карточки таблиц, переименования и
переносы без смены поведения, эксперименты в `notebooks/`. Это делается сразу.

## Цикл

1. **План.** Перечисли поведения (дано — когда — тогда) со ссылками на FR. Для изменения из OpenSpec план уже
   в specs и tasks.
2. **Красный.** Тест pytest на каждое поведение; имя говорит о поведении
   (`test_run_sql_blocked_without_validate`). Запусти только его — `uv run pytest tests/test_x.py::test_y -q` —
   и убедись, что падает по нужной причине.
3. **Зелёный.** Минимальный код, чтобы прошло. Без «заодно».
4. **Рефакторинг.** Улучшай при зелёных тестах; в конце — `uv run pytest -q` целиком.

## Правила

- Правишь поведение без теста — сначала характеризационный тест на то, что есть.
- Тесты офлайн: SQLite, сценарная модель (`harness/llm/scripted.py`), демо-DWH из `tests/conftest.py`. Сеть,
  OpenRouter и живой DWH в тестах не нужны.
- Время — через конфиг (`prompt.now`), а не через подмену системных часов.
- Параметризация — `pytest.mark.parametrize`; общие фикстуры — в `conftest.py`.
- Мутационное тестирование пока не используем (пункт в `TODO.md`).
