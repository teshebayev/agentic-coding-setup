# Правило: проверки в tasks.md — автоматические

Раскладывая изменение на задачи, проверку делай тестом, а не «проверить вручную».

| Уровень | Чем | Когда |
|---|---|---|
| Юнит | pytest на SQLite, офлайн | всегда |
| Сценарий хода | сценарная модель + демо-DWH (`demo.yml`, `prompt.now` = 2026-09-17) | меняется цикл, инструменты, проверки ответа |
| Replay | `harness.cli verify <сессия>` по демо-сессии; субагент `replay-reviewer` | затронуты `harness/core`, `harness/context`, payload событий |
| Оба профиля хранилища | `tests/test_postgres_storage.py` (нужны `HARNESS_PG_*`) | затронут `harness/storage` |
| Плейбук | `tests.yml` + `uv run pytest eval -m live` | меняется знание; **живой DWH — только с разрешения пользователя** |
| Контрольные вопросы | `python -m eval.run_control` | меняется промпт или модель; стоит денег — согласовать |

Хорошо: `- [ ] 4.2 Тест: run_sql без validate_sql отклоняется (FR3)`.
Плохо: `- [ ] 4.2 Проверить вручную, что SQL блокируется`.

Если проверка невозможна офлайн — так и напиши в задаче и вынеси в Open Questions.
