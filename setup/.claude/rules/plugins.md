# Правило: плагины и слои конфига

Подробно — `harness/README.md` (таблица плагинов и хуков); чек-лист нового плагина — скилл `harness-plugin`.

- Ядро ничего не знает про DWH. Поведение — плагины: `register(ctx)` вешает хуки (`pre_step`, `pre_tool`,
  `post_tool`, `post_step`, `stop_check`, `turn_stopping` — порядок по priority), секции промпта,
  инструменты, сервисы (`ctx.services[...]`).
- Слои `base.yml → dwh.yml → local.yml` (+ `demo.yml`, `docker.yml`; выбор — `--layers` или
  `HARNESS_CONFIG_LAYERS`) сливаются глубоко, **списки
  заменяются целиком**. Плагин из `base.yml` обязан быть и в `dwh.yml` (`dwh.yml` — надмножество;
  `demo.yml`/`docker.yml` наследуют его список). Хук после правки проверяет это.
- Что реально работает — смотри последний слой с `plugins:`, а не наличие модуля в коде.
- Риск, скоуп и бюджеты инструментов MCP — в конфиге харнесса (`mcp.servers.*.tools`), не в сервере.
- Сбой необязательного плагина (Langfuse, injector, examples) не роняет ход — так и пиши новые.
- Новые настройки — с безопасным значением по умолчанию в `base.yml`; секреты — только `${VAR:-}` из `.env`.
