# Файлы пользователя загружаются по ссылке харнесса, а не через LibreChat

Менеджерам нужно передавать агенту файлы клиента (первый сценарий — сверка остатков, до 50 000 строк). Харнесс
принимает файл на своей странице загрузки по одноразовой ссылке, привязанной к пользователю и беседе. Ссылку
выдаёт команда `/файл` или инструмент модели. Файл попадает в сессию событием лога, а не текстом в сообщении.
Скрепкой в LibreChat не пользуемся: фронт LibreChat — чужой проект, и харнесс должен получать сам файл, а не
текст, который из него сделал кто-то другой.

## Рассмотренные варианты

- **Форк фронта LibreChat с кнопкой загрузки в харнесс.** Отказались: нужны своя сборка образа и перенос правок
  на каждое обновление LibreChat.
- **«Upload as Text» в LibreChat.** Отказались: LibreChat сам извлекает текст и вклеивает его в сообщение, то есть
  весь файл попадает в контекст модели (экономии токенов нет), а формат вклейки — внутреннее дело LibreChat и
  может потерять структуру таблицы.
- **RAG / file_search LibreChat.** Отказались: поиск по кускам не годится для сверки всех строк, плюс отдельный
  сервис RAG API.

## Последствия

- Менеджер уходит из чата на страницу загрузки и возвращается обратно. Это лишний шаг, зато фронт не трогаем.
- У страницы загрузки нет ключа API. Защищает её токен в ссылке: короткий срок жизни, привязка к `X-User-Id` и
  `X-Conversation-Id`.
- Если LibreChat научится передавать сами файлы в custom endpoint, решение стоит пересмотреть новым ADR.
