# Spec Delta: file-upload

## Purpose

Как загруженный файл пользователя попадает в харнесс в обход вложений LibreChat: по ссылке, привязанной к
пользователю и беседе, с проверкой формата и размера, с хранением только у владельца и ограниченным сроком
жизни.

## ADDED Requirements

### Requirement: Команда чата выдаёт ссылку на загрузку
<!-- реализует FR1 из add-file-upload -->
Сообщение `/файл`, `/загрузить` или `/upload` (без учёта регистра, без аргументов) SHALL получать в ответ ссылку
на загрузку для текущей беседы. Ход при этом MUST NOT запускаться, модель MUST NOT вызываться. Если у беседы
ещё нет сессии, она создаётся и привязывается к беседе, как при обычном вопросе.

#### Scenario: Команда в существующей беседе
<!-- реализует FR1 из add-file-upload -->
- **WHEN** зарегистрированный пользователь пишет `/файл` в беседе с уже существующей сессией
- **THEN** ответ содержит ссылку на загрузку для этой сессии, а в логе сессии не появляется ни одного события
  хода и ни одного вызова модели

#### Scenario: Команда первой репликой новой беседы
<!-- реализует FR1 из add-file-upload -->
- **WHEN** пользователь начинает новую беседу сообщением `/Upload`
- **THEN** создаётся сессия этого пользователя, ответ содержит ссылку для неё, и следующий вопрос в той же беседе
  попадает в ту же сессию

### Requirement: Модель может попросить файл
<!-- реализует FR2 из add-file-upload -->
Модели SHALL быть доступен инструмент `request_upload`, который возвращает ссылку на загрузку для текущей сессии.
После его вызова ход MUST останавливаться с причиной `awaiting_user`, а ссылка MUST попадать в ответ
пользователю.

#### Scenario: Вопрос про файл без файла
<!-- реализует FR2 из add-file-upload -->
- **WHEN** сценарная модель на вопрос «сверь с файлом клиента» вызывает `request_upload`
- **THEN** ход завершается с `awaiting_user`, пользователь видит ссылку на загрузку, другие инструменты в этом
  ходу больше не вызываются

### Requirement: Ссылка подписана, коротко живёт и одноразова
<!-- реализует FR3, NFR-S1 из add-file-upload -->
Ссылка на загрузку SHALL быть подписана ключом харнесса от пользователя, сессии и срока и работать без ключа
API. Срок жизни — `uploads.link_ttl_minutes` (по умолчанию 30). После первой успешной загрузки ссылка MUST
отклоняться. Отклонённая ссылка MUST NOT сохранять файл.

#### Scenario: Просроченная ссылка
<!-- реализует FR3 из add-file-upload -->
- **WHEN** файл отправляют по ссылке через 31 минуту после её выдачи
- **THEN** загрузка отклоняется с текстом «ссылка устарела, запросите новую командой /файл», в хранилище
  ничего не появляется

#### Scenario: Повторная загрузка по той же ссылке
<!-- реализует FR3 из add-file-upload -->
- **WHEN** по ссылке уже загружен файл и по ней отправляют второй
- **THEN** вторая загрузка отклоняется как использованная ссылка, первый файл остаётся без изменений

#### Scenario: Подделанная подпись или чужая сессия
<!-- реализует NFR-S1 из add-file-upload -->
- **WHEN** в ссылке заменён id сессии или подпись
- **THEN** загрузка отклоняется, ответ не раскрывает, существует ли такая сессия

#### Scenario: Отключённый пользователь
<!-- реализует NFR-S1 из add-file-upload -->
- **WHEN** пользователя, получившего ссылку, отключили до загрузки
- **THEN** загрузка по его ссылке отклоняется

### Requirement: Допустимые форматы
<!-- реализует FR4 из add-file-upload -->
Загрузка SHALL принимать только форматы из `uploads.formats` (по умолчанию xlsx, xls, csv). Формат определяется
по расширению и содержимому. Файл другого формата MUST отклоняться с перечнем допустимых.

#### Scenario: Неподдерживаемый формат
<!-- реализует FR4 из add-file-upload -->
- **WHEN** пользователь загружает `акт.pdf` при настройках по умолчанию
- **THEN** загрузка отклоняется с текстом, в котором перечислены xlsx, xls, csv, ссылка остаётся годной

#### Scenario: Расширение не совпадает с содержимым
<!-- реализует FR4 из add-file-upload -->
- **WHEN** загружают текстовый файл, переименованный в `остатки.xlsx`
- **THEN** загрузка отклоняется как повреждённый или неверный файл, ссылка остаётся годной

### Requirement: Пределы размера
<!-- реализует FR5 из add-file-upload -->
Файл больше `uploads.max_bytes` (по умолчанию 10 МБ) или с числом строк данных больше `uploads.max_rows`
(по умолчанию 50 000) SHALL отклоняться целиком. Частичный разбор и сохранение MUST NOT происходить.

#### Scenario: Слишком много строк
<!-- реализует FR5 из add-file-upload -->
- **WHEN** загружают csv с 50 001 строкой данных
- **THEN** загрузка отклоняется с текстом о пределе 50 000 строк, ни оригинал, ни артефакт не сохраняются

#### Scenario: Ровно на пределе
<!-- реализует FR5 из add-file-upload -->
- **WHEN** загружают csv ровно с 50 000 строками данных
- **THEN** загрузка принимается

### Requirement: Доступ только владельцу
<!-- реализует FR9 из add-file-upload -->
Загруженный файл и сделанные из него артефакты SHALL быть доступны только сессии, к которой привязана ссылка,
то есть её владельцу и роли `admin`. Отдать оригинал наружу MUST NOT было возможно ни одним роутом или
инструментом.

#### Scenario: Чужая сессия
<!-- реализует FR9 из add-file-upload -->
- **WHEN** модель в сессии пользователя B вызывает `read_upload` с id загрузки из сессии пользователя A
- **THEN** вызов возвращает ошибку «загрузка не найдена»

### Requirement: Срок хранения оригинала
<!-- реализует FR10 из add-file-upload -->
Оригиналы загрузок старше `uploads.retention_days` (по умолчанию 7) SHALL удаляться командой чистки выгрузок в
обоих профилях хранилища.

#### Scenario: Чистка
<!-- реализует FR10 из add-file-upload -->
- **WHEN** запускается чистка, а в хранилище лежат загрузки возрастом 8 и 2 дня
- **THEN** первая удалена, вторая осталась, в отчёте команды указано число удалённых загрузок

### Requirement: Оригинал вне лога событий
<!-- реализует NFR-S3 из add-file-upload -->
Оригинал файла SHALL храниться только в объектном хранилище профиля. Лог событий MUST содержать не больше
превью из первых строк.

#### Scenario: Большой файл в логе
<!-- реализует NFR-S3 из add-file-upload -->
- **WHEN** загружен файл на 50 000 строк и прошёл следующий ход
- **THEN** ни одно событие сессии не содержит больше `results.preview_rows` строк данных файла
