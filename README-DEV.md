# Агентный сетап: руководство разработчика

Как работать в проекте с этим сетапом и как менять сам сетап. Установка и общий обзор: [README.md](README.md).

Сетап превращает Claude Code из помощника по запросу в участника процесса. Изменения идут через спецификацию, опасные
команды останавливаются хуками, а тесты и поиск секретов срабатывают сами. Команды ниже взяты из шаблона (Python, `uv`).
В вашем проекте точные команды смотрите в его `CLAUDE.md`.

## С чего начать

### Если сетап уже в проекте

```bash
npm i -g @fission-ai/openspec@1.14.3
openspec config set telemetry.enabled false
uvx pre-commit install               # на каждой машине отдельно
```

Затем запустите `claude` в корне репозитория. Сетап настроен, если:

- при старте `doctor.sh` не выводит замечаний;
- в `/hooks` видны четыре хука;
- по `/` видны `/opsx:*`, `/grill-with-docs` и команды проекта.

Claude Code должен быть версии 2.1.295 или новее. Плагин superpowers ставится через `/plugin`, если проект его использует:
тогда его TDD, systematic-debugging и verification работают внутри `/opsx:apply`.

### Если сетапа в проекте ещё нет

Откройте Claude Code в корне своего репозитория и напишите:

> Прочитай `<путь>/agentic-coding-setup/ADAPT.md` и перенеси сетап в этот репозиторий по нему.

Агент изучит проект, задаст один раунд вопросов, перенесёт файлы и прогонит проверки. Коммитить он не будет.

## Как вести изменение

```
неясная идея ── /grill-with-docs ──┐
                                   ├─→ /opsx:propose ─→ /opsx:apply ─→ /opsx:archive ─→ коммит
исследование ── /opsx:explore ─────┘    (та же сессия)   (новая сессия)
```

| Шаг | Что делает | Результат |
|---|---|---|
| `/grill-with-docs` | Интервью по неясной идее: на каждый вопрос агент предлагает ответ, факты ищет в коде сам | `GLOSSARY.md`, `docs/adr/` |
| `/opsx:explore` | Исследование без кода: варианты, разбор устройства | разговор |
| `/opsx:propose` | Создаёт изменение: требования с ID, дельта-спеки, design при реальном выборе, задачи | `openspec/changes/<имя>/` |
| `/opsx:apply` | Выполняет задачи по порядку и отмечает их в `tasks.md` | код и тесты |
| `/opsx:apply-sequential` | То же для больших изменений: каждая задача в свежем субагенте, строго по очереди | код и тесты |
| `/opsx:archive` | Вливает дельта-спеки в `openspec/specs/` и переносит изменение в архив | `openspec/changes/archive/` |

Образец готового изменения лежит в [examples/](examples/openspec-change-add-file-upload/).

Что важно соблюдать:

- **`/grill-with-docs` запускайте отдельно, не изнутри `/opsx:*`.** Затем в той же сессии вызовите `/opsx:propose`, иначе
  договорённости останутся только в разговоре.
- **`/opsx:apply` запускайте в новой сессии.** Старый контекст даёт несвязный код.
- **Мелочи изменения не требуют.** Опечатку или однострочный баг с тестом просто чините.
- **Просите коммит явно.** Сам агент не коммитит.

## Что срабатывает само

| Когда | Хук | Что делает |
|---|---|---|
| Старт сессии | `doctor.sh` | Проверяет инструменты, версии, плагин, pre-commit, секреты вне `.gitignore` и посторонний `PYTHONPATH`. Если всё в порядке, молчит. Сессию не блокирует |
| Перед вызовом инструмента | `guard.sh` | Запрещает опасное или спрашивает разрешение. Если сам guard сломан, вызов блокируется |
| После правки файла | `post-edit.sh` | Запускает линтер и проверки границ. Замечания получает агент, правка не блокируется |
| Конец ответа агента | `stop-tests.sh` | Запускает офлайн-тесты, если менялись файлы, от которых они зависят. При проблеме возвращает агента к работе |

Поведение `stop-tests.sh`, которое стоит знать:

- Об одном и том же состоянии файлов он сообщает один раз. Если агент закончил ответ с красными тестами, повторного
  напоминания не будет, пока файлы не изменятся.
- В свежей копии репозитория первый запуск пройдёт один раз, даже если вы ничего не меняли.
- Красные тесты, таймаут, отсутствие тестов и сбой запуска дают разные сообщения. Сбой запуска чаще всего означает
  проблему окружения, а не кода.

## Что можно запускать

Правило лежит в `.claude/rules/testing-runs.md`, а `guard.sh` его страхует.

| Уровень | Что входит |
|---|---|
| Свободно | Офлайн-тесты, линтер, `openspec`, обычные команды git и поиск по `src/` |
| С разрешения | `git push`, `git reset --hard`, `git clean -f`, `git restore`, `git branch -D`, `git stash drop`, `sudo`, `rm -r` (кроме кэшей и `/tmp`), `grep -r .`, `rg --no-ignore`, `tar .`, а также деплой, платные API и живые данные проекта |
| Никогда | Чтение `.env` и `.env.*` (кроме примеров), `*.pem`, `~/.ssh`, `~/.aws`, `~/.kube`; `git push --force`, `--no-verify`, `curl \| sh`, `rm -r` по широкой цели, правка архива изменений |

`guard.sh` не различает смысл текста. Команда с упоминанием `.env`, например в сообщении коммита, будет отклонена.
Переформулируйте текст: это ожидаемое поведение.

## Проверки вне сессии

Хуки работают только внутри сессии Claude Code. Людей и другие инструменты страхуют:

| Где | Когда | Что проверяет |
|---|---|---|
| `.pre-commit-config.yaml` | При `git commit` | gitleaks, линтер, тесты хуков (если они менялись) |
| `.github/workflows/ci.yml` | При push в `main` и в pull request | Линтер, офлайн-тесты, тесты хуков, `openspec validate`, gitleaks по всей истории |

CI останавливает слияние только при включённой защите `main`. Для приватного репозитория на бесплатном плане GitHub она
недоступна, поэтому там красный CI лишь сообщает об ошибке.

## Что есть в наборе

| Что | Где | Зачем |
|---|---|---|
| Правила | `.claude/rules/` | Без `paths:` грузятся всегда, с `paths:` только при работе с этими файлами |
| Скиллы | `.claude/skills/` | Процедуры «как сделать X». `openspec-*` генерируются, сторонние править нельзя: [реестр](setup/.claude/skills/README.md) |
| Субагенты | `.claude/agents/` | Ревьюер одного класса ошибок. Вызывается перед завершением изменения |
| `/uncommitted-files` | `.claude/commands/` | Чек-лист незакоммиченных файлов |
| `/fix-uncommitted` | `.claude/commands/` | Разбор этих файлов: по субагенту на файл, без коммитов |
| `/refactor-claude-md` | `.claude/commands/` | Аудит `CLAUDE.md`. С `--apply` записывает изменения |

## Как менять сетап

### Куда класть новое знание

`CLAUDE.md` грузится в каждую сессию, поэтому каждая его строка стоит токенов всегда. Выбирайте самое узкое место:

| Если это | Куда |
|---|---|
| Нарушение можно поймать скриптом | Хук или `guard.sh`, в тексте только причина |
| Правило одной области кода | `.claude/rules/` с `paths:` |
| Повторяющаяся процедура | Скилл в `.claude/skills/` |
| Длинная справка | `docs/`, в `CLAUDE.md` только ссылка |
| Решение, которое дорого отменить | ADR в `docs/adr/` |
| Термин проекта | `GLOSSARY.md` |
| Нужно в каждой сессии | `CLAUDE.md`, коротко |

### Как добавить запрет в guard

1. Добавьте проверку в блок «Адаптация» в `scripts/agent/guard.sh`.
2. Добавьте в `scripts/agent/test-hooks.sh` две строки: что правило ловит и похожую обычную команду, которую оно не должно
   задевать.
3. Запустите `scripts/agent/test-hooks.sh`. Ожидаемый итог: «провалено: 0».
4. Если это новый секрет, добавьте его также в `testing-runs.md`, `.gitignore`, `permissions.deny` и `secret_files` в
   `doctor.sh`.

Хук-настройки подхватываются после перезапуска Claude Code.

### Как менять сам шаблон

Правьте файлы в `setup/` и держите в согласии инструкцию `instructions/<тот же путь>.md`. Перед коммитом запустите:

```bash
cd setup && scripts/agent/test-hooks.sh
```

Вложенные `.gitignore` скрывают от git два файла шаблона. Новые версии этих путей добавляются принудительно:

```bash
git add -f setup/.claude/settings.local.json setup/.superpowers/sdd/.gitignore
```

Откат к исходному снимку шаблона: `git checkout df42a76`.

## Если что-то не работает

| Симптом | Причина | Что сделать |
|---|---|---|
| Любой вызов инструмента блокируется с `blocking because onFailure is "block"` | `guard.sh` не запускается | Проверьте, что файл на месте и исполняемый: `chmod +x scripts/agent/*.sh`, что установлен `jq`, затем запустите `scripts/agent/test-hooks.sh` |
| pytest падает с `No module named 'yaml'` или похожей ошибкой в чужом пакете | `PYTHONPATH` подмешивает посторонние пакеты, например ROS | В сессии это чинит блок `env` в `settings.json`. В своём терминале: `env -u PYTHONPATH uv run pytest -q` |
| Проекту нужен `PYTHONPATH` | Его очищают настройки и хуки | Уберите блок `env` из `settings.json` и `unset PYTHONPATH` из хуков |
| Хук мешает в конкретной сессии | | Отключите его через `/hooks` или в `.claude/settings.local.json`: этот файл не коммитится |
| Агент закончил с красными тестами и больше не напоминает | Хук сообщает один раз на состояние файлов | Запустите тесты сами или попросите агента их починить |
| `git commit` падает на gitleaks | В коммите похоже на секрет | Уберите секрет и смените его, если он настоящий. Для тестовых данных настройте `.gitleaks.toml` |
| `doctor.sh` пишет «pre-commit не установлен» | Хук ставится на каждую машину отдельно | `uvx pre-commit install` |
| `/opsx:*` не работают | Не установлен или не в `PATH` CLI OpenSpec | `npm i -g @fission-ai/openspec@1.14.3`, проверьте `openspec --version` |

Проверить хук вручную можно, подав ему JSON:

```bash
echo '{"tool_name":"Bash","tool_input":{"command":"git push"}}' | scripts/agent/guard.sh
```

## Ограничения

- **`guard.sh` страхует от промаха, но не является границей безопасности.** Чтение секрета через `python -c` или
  `ls | xargs cat` он не поймает. Настоящую границу для Bash даёт только песочница Claude Code; в этом сетапе она не
  настроена и не проверялась. Не храните в репозитории секреты, утечка которых недопустима.
- **Трассируемость не проверяется автоматически.** Правило требует для каждого требования реализацию и тест, но
  `/opsx:archive` пропустит требование без теста. Перед архивом проверяйте сами: `grep -rn "FR2" src tests`.
- **Падение CI на GitHub не проверялось.** На учебном проекте подтверждён только зелёный запуск.
- **Хук `stop-tests.sh` рассчитан на коды выхода pytest.** Для другого раннера их нужно сверить и поправить.
- **Superpowers проверяется только через `doctor.sh`.** Без плагина цикл `/opsx:*` работает, но его TDD и
  verification внутри `/opsx:apply` недоступны.
