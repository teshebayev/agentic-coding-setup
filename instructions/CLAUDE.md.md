# Инструкция агенту: `CLAUDE.md`

- **Что это:** главная память проекта для Claude Code: карта репозитория, команды, архитектурные инварианты, ловушки, процесс
- **Когда подхватывается:** в каждой сессии целиком, до первого сообщения. Каждая строка стоит токенов всегда
- **Действие при переносе:** **переписать** — содержимое про проект «DWH-аналитик», в вашем проекте нужно своё

## Что в файле сейчас (проект «DWH-аналитик»)

~117 строк, на английском (сам файл), но первой строкой требует писать docs/комментарии/коммиты/OpenSpec по-русски.
Разделы:
- **What this is** — харнесс «DWH-аналитик»: LLM пишет SQL, харнесс валидирует, выполняет read-only через MCP,
  проверяет ответ. `IMPORTANT:` читать соседний код, тесты и README модуля перед новым кодом.
- **Commands** — `uv sync`, `uv run pytest -q` (офлайн, ≈13 с), один тест, `ruff`, офлайн-демо без ключей
  (SQLite + сценарная модель), реальный запуск, API, eval, команды витрин. Ссылка на `testing-runs.md` —
  что можно запускать без спроса.
- **Architecture (big picture)** — путь старта и 6 пунктов-инвариантов (всё плагин; event log и детерминированный
  replay; DWH только через MCP; два профиля хранилища; знание растёт через ревью; LibreChat через OpenAI-совместимый
  API). Каждый пункт — 1–2 строки и стрелка `→ .claude/rules/<файл>.md`.
- **Gotchas** — замороженная дата демо, `hard_exit` против краша pyarrow, часовой пояс DWH, `docker compose config`
  печатает секреты, список файлов с доступами, которые нельзя читать.
- **Development workflow (OpenSpec)** — схема `/grill-with-docs → /opsx:propose → /opsx:apply → /opsx:archive`,
  когда изменение не нужно, доменные скиллы, субагент, команды, хуки.
- **Rules** — таблица всех файлов `.claude/rules/` со scope и темой.

## Что должно быть в вашем проекте

Тот же скелет, но про ваш проект, 60–150 строк:
1. **Что это** — 2–4 предложения + язык документации/коммитов + одна `IMPORTANT:`-строка о самом частом промахе.
2. **Commands** — точные, проверенные команды: установка, все тесты, один тест, линт/типы, локальный запуск без
   внешних зависимостей (если есть), реальный запуск. Ссылка на `.claude/rules/testing-runs.md`.
3. **Architecture** — только то, что не видно из дерева файлов и ломается при незнании; каждый пункт ведёт в
   правило из `.claude/rules/`.
4. **Gotchas** — неочевидные ловушки окружения и кода; файлы с секретами, которые нельзя читать.
5. **Workflow** — OpenSpec-цикл (если берёте), имена своих скиллов, субагентов, команд, что делают хуки.
6. **Rules** — таблица, совпадающая с реальным содержимым `.claude/rules/`.

Не нужно: дерево файлов, содержимое `package.json`/`pyproject.toml`, общие советы по языку.

## Шаги адаптации

1. Не копируй наш текст. Собери факты сам: менеджер пакетов, команды тестов и линта (запусти их и замерь время),
   точки входа, README модулей, файлы с секретами.
2. Спроси у пользователя то, чего нет в коде: язык артефактов, что опасно запускать, 3–7 главных инвариантов.
3. Напиши файл по скелету выше. Разделы Architecture и Rules заполняй после того, как готовы правила.
4. Проверь: каждый упомянутый путь существует (`ls`), каждая команда отрабатывает, таблица правил = `ls .claude/rules`.
5. В конце запусти `/refactor-claude-md` (режим отчёта) и убери лишнее.
