# Инструкция агенту: `scripts/agent/post-edit.sh`

- **Что это:** PostToolUse-хук после правки файла: быстрые проверки, замечания передаются Claude, ничего не блокирует
- **Когда подхватывается:** после каждого Edit/Write/MultiEdit (`.claude/settings.json`); вывод — JSON с `additionalContext` (обычный stdout PostToolUse Claude не видит)
- **Действие при переносе:** **подстроить** — каркас общий, поменять команды, пути и примеры под проект

## Что в файле сейчас (проект «DWH-аналитик»)

- Для `.py`: `uv run ruff check --output-format concise <файл>`.
- Для `harness/*.py`: grep на `import dwh_analyst_mcp` — нарушение границы MCP.
- Для `harness/config/base.yml|dwh.yml`: `scripts/agent/check_plugin_layers.py`.
- Все замечания собираются в `notes` и уходят одним `additionalContext`.

## Что должно быть в вашем проекте

Проверки, которые быстрые (секунды), смотрят только на изменённый файл и ловят частые ошибки: линтер по
расширению файла, запрет импорта через границу слоёв, согласованность конфигов. Без автофикса (агент правит сам,
видя замечание) и без полного прогона тестов (это делает Stop-хук).

## Шаги адаптации

1. Замени ветку `.py`/ruff на линтер вашего стека по расширению (`*.ts|*.tsx` → `npx eslint <файл>`,
   `*.go` → `gofmt -l` / `go vet ./<пакет>`). Команда должна укладываться в несколько секунд.
2. Замени проверку `harness/` ↔ `dwh_analyst_mcp` на свои границы (например `src/domain/**` не импортирует
   `src/infra`) или удали.
3. Удали вызов `check_plugin_layers.py` или замени на свою проверку согласованности.
4. `export PATH="$HOME/.local/bin:$PATH"` нужен, если инструменты стоят в `~/.local/bin`; оставь или поправь.
5. Дымовой тест: `echo '{"tool_input":{"file_path":"'$PWD'/<файл с ошибкой>"}}' | scripts/agent/post-edit.sh`
   → JSON с замечанием.

## Связи с другими файлами

`.claude/settings.json`, `check_plugin_layers.py`, доменные правила (границы).
