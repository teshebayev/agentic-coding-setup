# Инструкция агенту: `scripts/agent/check_plugin_layers.py`

- **Что это:** доменная проверка-инвариант: каждый плагин из `harness/config/base.yml` есть в `dwh.yml`
- **Когда подхватывается:** из `post-edit.sh`, когда правится один из этих двух конфигов
- **Действие при переносе:** **заменить своим или удалить** — доменный файл нашего проекта, служит образцом формы

## Что в файле сейчас (проект «DWH-аналитик»)

Читает списки `plugins:` двух слоёв YAML, печатает недостающие и возвращает код 1. Пример того, как правило (`plugins.md`: «списки слоёв заменяются целиком») превращено в автоматическую проверку.

## Что должно быть в вашем проекте

Своя проверка согласованности, если в проекте есть инвариант между файлами, который легко нарушить (переводы во всех локалях, env-переменная в `.env.example` и в конфиге, роут в списке прав). Иначе — ничего.

## Шаги адаптации

1. Удали файл и его вызов из `post-edit.sh`.
2. Если пользователь назвал инвариант между файлами — напиши аналог (короткий скрипт, код выхода 1 и понятное сообщение) и вызови его из `post-edit.sh` при правке соответствующих файлов.

## Связи с другими файлами

`post-edit.sh`, `.claude/rules/plugins.md`.
