# Инструкция агенту: `scripts/agent/stop-tests.sh`

- **Что это:** Stop-хук: когда агент заканчивает ответ, прогоняет офлайн-тесты, если код менялся с последнего зелёного прогона
- **Когда подхватывается:** на событии Stop (`.claude/settings.json`); красные тесты возвращают `decision: block` — Claude продолжает работу; `stop_hook_active` не даёт зациклиться
- **Действие при переносе:** **подстроить** — каркас общий, поменять команды, пути и примеры под проект

## Что в файле сейчас (проект «DWH-аналитик»)

- Отпечаток = sha1 от `git diff HEAD -- '*.py'` и содержимого новых `.py`; пустой — выход.
- Совпал с `.git/claude-last-green` — тесты уже зелёные на этом коде, выход.
- Иначе `timeout 300 uv run --quiet pytest -q -x`; успех → записать отпечаток; провал → `block` с 25 последними
  строками вывода.

## Что должно быть в вашем проекте

Тот же механизм с вашими расширениями кода и командой быстрых офлайн-тестов. Если полный прогон дольше 2–3
минут — запускать быстрый поднабор (юнит-тесты, затронутый пакет), иначе каждая остановка будет долгой.

## Шаги адаптации

1. `'*.py'` (в двух местах) → расширения вашего кода (`'*.ts' '*.tsx'`, `'*.go'`…).
2. `uv run --quiet pytest -q -x` → ваша команда (`npx vitest run --bail 1`, `go test ./...`), без watch-режима.
3. `timeout 300` и `timeout` у Stop в `settings.json` — под реальное время (+запас).
4. Проверка: поменяй файл кода так, чтобы тест упал, заверши ответ — хук должен вернуть агента к работе.
