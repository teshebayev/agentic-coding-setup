# Инструкция агенту: `scripts/agent/test-hooks.sh`

- **Что это:** тесты всех хуков и связности настроек: около 180 проверок за несколько секунд, на bash и jq
- **Когда подхватывается:** вручную при правке хуков, в pre-commit (если менялись `scripts/agent/`, `settings.json`, `.gitignore`) и в CI
- **Действие при переносе:** **подстроить** — правятся только блоки «Адаптация»

## Что в файле сейчас (проект «DWH-аналитик»)

- **guard:** таблицы вызовов с ожиданием `allow`, `ask` или `deny`: секреты, разрушительные команды, архив изменений,
  обычная работа, которая не должна прерываться, сбой хука.
- **Адаптация, команды проекта:** наши секретные файлы и опасные команды (`ACCESS.local.md`, `marts`, `harness.cli`…).
- **stop-tests:** работает на копии хука с поддельным раннером вместо `test_cmd`, поэтому не нужны ни `uv`, ни pytest.
- **Адаптация, вверху файла:** `code_file`, `config_file` (должны попадать в `watch` из `stop-tests.sh`), `rc_failed`, `rc_no_tests`.
- **doctor, post-edit, uncommitted-files:** основные сценарии и исправная машина, где `doctor` молчит.
- **Связность:** `onFailure: block` у guard, четыре хука, все скрипты из настроек существуют, таймаут `Stop` больше
  `test_timeout`, `permissions.deny` не пуст, `.gitignore` закрывает `secret_files` из `doctor.sh`.

## Что должно быть в вашем проекте

Тот же файл с вашим блоком команд проекта. Новое правило в `guard.sh` — новая строка таблицы: и то, что правило ловит,
и похожая обычная команда, которую оно не должно задевать.

## Шаги адаптации

1. Перепиши блок «секреты и опасные команды проекта»: каждая ваша проверка из `guard.sh` даёт хотя бы одну строку.
2. `code_file`, `config_file` — файлы, которые попадают в ваш `watch`. Другой раннер — поправь `rc_failed`, `rc_no_tests`.
3. Запусти: `scripts/agent/test-hooks.sh` → «провалено: 0», код выхода 0.
4. Проверь, что тесты умеют падать: убери одну из своих проверок в `guard.sh`, запусти — должен быть провал; верни.
