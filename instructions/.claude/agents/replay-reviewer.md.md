# Инструкция агенту: `.claude/agents/replay-reviewer.md`

- **Что это:** проектный субагент-ревьюер одного класса ошибок (детерминизм replay и совместимость лога событий)
- **Когда подхватывается:** по описанию (`description`) — главный агент вызывает его сам, когда дифф задевает перечисленные пути; также его явно требуют `openspec/config.yaml` (operations.apply) и `/opsx:apply-sequential`
- **Действие при переносе:** **заменить своим или удалить** — доменный файл нашего проекта, служит образцом формы

## Что в файле сейчас (проект «DWH-аналитик»)

Фронтматтер: `name`, `description` (когда вызывать), `tools: Bash, Read, Grep, Glob` (только чтение, код не
правит), `model: inherit`. Тело: контекст (правило `event-log.md`, README модулей); шаги — `git diff`, по каждому
пункту чек-листа (чистота `build_request`, источник данных промпта, совместимость payload, префикс кэша, запись в
лог) вердикт «ок / проблема / не затронуто» со ссылкой `файл:строка`; прогон целевых тестов и `harness.cli verify`;
формат отчёта; «не выдумывай проблем без доказательства в коде».

## Что должно быть в вашем проекте

0–2 своих ревьюера на самые дорогие ошибки проекта: например `migration-reviewer` (обратная совместимость схемы),
`api-compat-reviewer` (публичный API/контракты), `security-reviewer` (авторизация, утечки данных). Та же форма:
один класс ошибок, только читающие инструменты, чек-лист с вердиктами и ссылками, целевые тесты, короткий отчёт.

## Шаги адаптации

1. Спроси пользователя, какой класс ошибок дороже всего и плохо ловится тестами. Нет такого — удали файл.
2. Создай `.claude/agents/<имя>.md` по образцу; `description` начни с «Ревью диффа на …» и перечисли пути, при
   изменении которых его вызывать.
3. Обнови упоминания `replay-reviewer`: `openspec/config.yaml` (operations.apply.guidance),
   `.claude/commands/opsx/apply-sequential.md`, `CLAUDE.md`, `docs/22-agentic-coding.md`, доменные скиллы.
4. Удали `replay-reviewer.md`.
