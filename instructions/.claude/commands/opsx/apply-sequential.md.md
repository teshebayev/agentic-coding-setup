# Инструкция агенту: `.claude/commands/opsx/apply-sequential.md`

- **Что это:** слэш-команда `/opsx:apply-sequential [имя]` — свой вариант `/opsx:apply` для больших изменений: каждая задача в свежем субагенте, строго по очереди
- **Когда подхватывается:** по вызову пользователя. **Не генерируется** OpenSpec — `openspec update` её не трогает
- **Действие при переносе:** **подстроить** — каркас общий, поменять команды, пути и примеры под проект

## Что в файле сейчас (проект «DWH-аналитик»)

Шаги 1–5 скилла `openspec-apply-change` в основном контексте (без кода); затем на каждую задачу один субагент
`general-purpose` не в фоне с промптом: путь к изменению, текст задачи с FR/NFR, context-файлы, «не коммить, только
эта задача, прогони `uv run pytest -q`, при неясности или живом DWH — остановись». Успех → `[x]` в tasks.md;
блокер → спросить. В конце `ruff`, `pytest`, при правке `harness/core|context` — `replay-reviewer`.

## Что должно быть в вашем проекте

То же с вашими командами тестов и линта, вашим условием «стоп» (что требует разрешения) и вашим ревьюером.

## Шаги адаптации

1. Замени `uv run pytest -q`, `uv run ruff check .` на ваши команды.
2. «нужен живой DWH» → ваше условие из `testing-runs.md` (прод, платный API…).
3. Замени `replay-reviewer` и пути `harness/core|context` на своего ревьюера и его пути, или убери пункт.
4. Положи файл после `openspec init` (он создаёт папку `opsx/`).
