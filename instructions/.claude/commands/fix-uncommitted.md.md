# Инструкция агенту: `.claude/commands/fix-uncommitted.md`

- **Что это:** слэш-команда `/fix-uncommitted`: проверить и поправить каждый незакоммиченный файл отдельным субагентом
- **Когда подхватывается:** по вызову пользователя
- **Действие при переносе:** **подстроить** — каркас общий, поменять команды, пути и примеры под проект

## Что в файле сейчас (проект «DWH-аналитик»)

Шаги: обновить чек-лист скриптом; на каждый `[ ]`-файл — один субагент `general-purpose` строго по очереди с
готовым промптом (до трёх циклов: диагностика VS Code `mcp__claude-vscode__getDiagnostics` + `ruff` → правка без
смены поведения → поиск дублей через grep, не объединять код через границу `harness/` ↔ `dwh_analyst_mcp` →
неиспользуемое → повтор; строгий формат ответа). `.md` проверяются только на битые ссылки. Отметка `[x]` после
каждого. В конце `ruff`, `pytest`, офлайн-демо. Без коммитов.

## Что должно быть в вашем проекте

Тот же процесс с вашим линтером, вашим запретом на объединение через границы слоёв и вашими финальными проверками.

## Шаги адаптации

1. `ruff check <путь>` → линтер/тайпчекер вашего стека (eslint, tsc --noEmit, golangci-lint…).
2. Пункт 3 промпта: замени границу `harness/` ↔ `dwh_analyst_mcp` на свою или убери.
3. Пункт 4 итога: замени `ruff`/`pytest`/офлайн-демо на ваши команды линта, тестов и дымового запуска.
4. JetBrains вместо VS Code — инструмент диагностики IDE называется иначе (например `get_file_problems` из
   JetBrains MCP); если IDE-диагностики нет — пункт пропускается сам.
