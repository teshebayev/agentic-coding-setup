# Инструкция агенту: `.claude/skills/harness-plugin/SKILL.md`

- **Что это:** доменный скилл-процедура нашего проекта
- **Когда подхватывается:** автоматически по `description`, когда задача совпадает с описанием; или `/harness-plugin`
- **Действие при переносе:** **заменить своим или удалить** — доменный файл нашего проекта, служит образцом формы

## Что в файле сейчас (проект «DWH-аналитик»)

Чек-лист нового плагина харнесса: найти похожий; приоритет хука по таблице в `harness/README.md`; всё для модели — через события; сбой не роняет ход; строка в `plugins:` и `base.yml`, и `dwh.yml`; тест на сценарной модели; replay-проверка; README/STATUS. Раздел «Готово, когда».

## Что должно быть в вашем проекте

2–4 своих скилла — процедуры «как сделать X в этом проекте», которые повторяются и где агент без чек-листа
забывает шаги. Форма:

```markdown
---
name: add-api-endpoint
description: Новый HTTP-эндпоинт — роут, схема, авторизация, тест, OpenAPI. Используй, когда пользователь просит
  добавить или изменить эндпоинт API.
---

# Новый эндпоинт

Правила — `.claude/rules/<область>.md`; образец — `<путь к хорошему примеру>`.

## Шаги
1. **Найди похожий** … 2. … N. **Документация** …

## Готово, когда
- тесты зелёные, линт чистый, …
```

`description` решает, когда Claude возьмёт скилл сам: «что делает» + «используй, когда …» с ключевыми словами.

## Шаги адаптации

1. Удали этот скилл (он про наш харнесс).
2. Найди повторяющиеся процедуры: спроси пользователя «что вы делаете чаще всего и где чаще забываете шаг?»,
   посмотри `git log --stat` — какие наборы файлов меняются вместе (миграция + модель + тест; роут + схема + тест).
3. На каждую процедуру — `.claude/skills/<имя>/SKILL.md` по форме выше, со ссылками на правила и образцовый файл.
4. Обнови `.claude/skills/README.md`, `CLAUDE.md` (Workflow → Domain skills), `docs/22-agentic-coding.md`.
