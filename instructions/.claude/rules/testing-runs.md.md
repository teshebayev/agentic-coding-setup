# Инструкция агенту: `.claude/rules/testing-runs.md`

- **Что это:** что агент может запускать свободно, что — только с разрешения, что — никогда
- **Когда подхватывается:** всегда, в каждой сессии: у правила нет `paths:` во фронтматтере, Claude Code грузит его как часть CLAUDE.md
- **Действие при переносе:** **переписать** — содержимое про проект «DWH-аналитик», в вашем проекте нужно своё

## Что в файле сейчас (проект «DWH-аналитик»)

- **Свободно:** офлайн-тесты, ruff, офлайн-демо с `demo.yml`, `harness.cli verify/events/context` по локальным
  сессиям, `marts check|sql`, `openspec …`.
- **Только с разрешения:** `pytest eval -m live` и `eval.run_control` (живой DWH, платная модель), `harness.cli
  ask|chat` с профилем по умолчанию, команды витрин `marts test|plan|status|cards|apply` (`apply` пишет в базу),
  `docker compose up/down/restart` на стенде, `migrate` на Postgres.
- **Никогда:** `docker compose config` без `--quiet`; чтение `.env`, `ACCESS.local.md`, `DWH-Tunnel-*`, `external/`.

## Что должно быть в вашем проекте

Три списка про ваш проект. «Только с разрешения» — всё, что трогает прод/стенд, общие ресурсы, стоит денег или
необратимо (деплой, миграции на общей БД, `terraform apply`, платные API, рассылки, публикация пакетов).
«Никогда» — чтение секретов и команды, которые их печатают.

## Шаги адаптации

1. Спроси пользователя: какие команды в проекте опасны или платные; где лежат секреты; что можно всегда.
2. Найди сам: скрипты деплоя, Makefile/package.json-скрипты, docker-compose, CI-конфиги, `.env*`.
3. Перепиши три списка.
4. **Синхронизируй с `scripts/agent/guard.sh`:** «никогда» → `decide deny`, «только с разрешения» → `decide ask`.
   Правило объясняет агенту, хук страхует.
