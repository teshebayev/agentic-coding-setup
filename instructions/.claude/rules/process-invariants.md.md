# Инструкция агенту: `.claude/rules/process-invariants.md`

- **Что это:** инварианты процесса разработки: размер изменений, архив, размер файлов, документация, коммиты
- **Когда подхватывается:** всегда, в каждой сессии: у правила нет `paths:` во фронтматтере, Claude Code грузит его как часть CLAUDE.md
- **Действие при переносе:** **подстроить** — каркас общий, поменять команды, пути и примеры под проект

## Что в файле сейчас (проект «DWH-аналитик»)

- Изменение = одна инициатива на 1–4 недели, имя `kebab-case` по смыслу (`add-…`, `fix-…`).
- Архив `openspec/changes/archive/**` неизменяем (исправление — новое изменение с `Supersedes:`); принятый ADR
  тоже не правится. `guard.sh` запрещает правку архива.
- Размер файлов: новый модуль — цель 200 строк, предел 300; список существующих больших файлов, которые ради
  правила не режут (`harness/storage/postgres.py`, `harness/tools/local/chart.py`, `harness/cli.py`).
- Документация в том же изменении: README/STATUS модуля, `docs/NN-*.md`, отложенное — в `STATUS.md` и `TODO.md`.
- Слои артефактов proposal → specs/design → tasks → код, нижний ссылается на ID верхнего.
- Свежий контекст для apply.
- Коммиты только по просьбе; заголовок по-русски, в теле — зачем и что проверено, с числом тестов.

## Что должно быть в вашем проекте

Те же пункты, с вашими конвенциями: какие документы обновляются вместе с кодом (README модулей, CHANGELOG,
ADR…), язык и формат коммитов (Conventional Commits?), список уже больших файлов-исключений.

## Шаги адаптации

1. Найди крупнейшие файлы: `git ls-files '*.<ext>' | xargs wc -l | sort -n | tail -10` — подставь в исключения
   (или удали пункт, если лимит размера не нужен; спроси).
2. Перепиши пункт «Документация» под реальные документы проекта (есть ли README в модулях, STATUS, TODO).
3. Перепиши пункт «Коммиты» под принятый формат (спроси язык и стиль; посмотри `git log --oneline -20`).
4. Если OpenSpec не берётся — удали пункты про архив, слои и apply.
