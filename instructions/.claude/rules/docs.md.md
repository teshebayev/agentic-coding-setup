# Инструкция агенту: `.claude/rules/docs.md`

- **Что это:** карта документации: какой документ для чего
- **Когда подхватывается:** только когда Claude читает или правит файлы из `paths:` (`docs/**`, `**/README.md`, `**/STATUS.md`, `TODO.md` и др.); иначе правило не занимает контекст
- **Действие при переносе:** **переписать** — содержимое про проект «DWH-аналитик», в вашем проекте нужно своё

## Что в файле сейчас (проект «DWH-аналитик»)

Всё по-русски. Таблица: целевая архитектурная спека; `docs/NN-*.md` — код как есть (новый — следующий номер +
ссылка в `docs/README.md`); `<модуль>/README.md` — как работает; `<модуль>/STATUS.md` — сделано/осталось с датами;
`TODO.md` — индекс отложенного; `PATTERNS.md`; `guide.md`; `openspec/specs/`; `docs/adr/`; `GLOSSARY.md`. Запрет
цитировать секретные файлы в коммитах.

## Что должно быть в вашем проекте

Таблица реально существующих в вашем проекте типов документов и их назначения; `paths:` — на эти файлы.

## Шаги адаптации

1. Найди документацию: `git ls-files '*.md' | grep -v node_modules | head -100`.
2. Спроси пользователя о назначении неочевидных документов; составь таблицу.
3. Обнови `paths:` и запрет на секретные файлы (те же, что в `guard.sh`).

## Связи с другими файлами

`process-invariants.md` (документация в том же изменении), `openspec/config.yaml` (rules.tasks, группа «Документация»).
