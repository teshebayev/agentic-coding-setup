# Инструкция агенту: `.claude/rules/knowledge.md`

- **Что это:** доменное правило одной области кода нашего харнесса
- **Когда подхватывается:** только когда Claude читает или правит файлы из `paths:` (`dwh-knowledge/**`, `dwh-analyst-mcp/demo/knowledge/**`, `harness/memory/**`); иначе правило не занимает контекст
- **Действие при переносе:** **заменить своим или удалить** — доменный файл нашего проекта, служит образцом формы

## Что в файле сейчас (проект «DWH-аналитик»)

Курируемое знание о DWH: `conventions.md`/`traps.md` идут в стабильный префикс промпта (каждая строка — токены); карточки таблиц, сгенерированные карточки не правятся руками; плейбуки (`SKILL.md` → `*.sql.j2` → `tests.yml`), черновики вне `playbooks/`; версия знания — хэш; демо-набор; цикл знания: агент-харнесс туда не пишет, кандидаты проходят ревью аналитика.

## Что должно быть в вашем проекте

Доменное правило — 4–8 инвариантов одной области кода, которые агент нарушит, если о них не знает, и которые
не видны из самого кода. Форма:

```markdown
---
paths:
  - "src/billing/**"
---

# Правило: <область>

Подробно — `src/billing/README.md`; чек-лист — скилл `<имя>` (если есть).

- **<Инвариант>.** Что нельзя/нужно и почему, одной-двумя строками.
- ...

После правки здесь: <какие тесты и проверки запустить>.
```

Хорошие кандидаты: граница слоёв или процессов, формат данных, который нельзя ломать (API, события, миграции),
обязательные проверки безопасности, «два варианта окружения, код должен работать в обоих».

## Шаги адаптации

1. Удали это правило из целевого проекта (оно про наш харнесс).
2. Спроси пользователя или найди сам: какие области кода самые хрупкие (`git log --oneline | grep -iE 'fix|исправ'`,
   README модулей, ревью-комментарии). На каждую область — одно правило по форме выше.
3. `paths:` — реальные глоб-шаблоны: проверь `ls` / `git ls-files '<glob>'`, что они что-то находят.
4. Если инвариант ловится скриптом (импорт через границу, рассинхрон конфигов) — добавь проверку в
   `scripts/agent/post-edit.sh`, а в правиле оставь причину.
5. Обнови таблицу правил в `CLAUDE.md` и ссылки из скиллов и субагентов, которые указывали на это правило.
