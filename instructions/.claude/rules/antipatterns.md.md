# Инструкция агенту: `.claude/rules/antipatterns.md`

- **Что это:** список антипаттернов процесса и кода, которые агент склонен повторять
- **Когда подхватывается:** всегда, в каждой сессии: у правила нет `paths:` во фронтматтере, Claude Code грузит его как часть CLAUDE.md
- **Действие при переносе:** **подстроить** — каркас общий, поменять команды, пути и примеры под проект

## Что в файле сейчас (проект «DWH-аналитик»)

- **Процесс** (общее): proposal без чисел в метриках; proposal как техзадание («сделать через Redis» — это
  design); расплывчатая ссылка на FR; договорённость, оставшаяся только в чате.
- **Код харнесса** (доменное): состояние в промпте мимо лога событий; плагин только в одном слое конфига;
  `harness` импортирует `dwh_analyst_mcp`; автогенерированная миграция; код под один профиль хранилища; правка
  `dwh-knowledge/` агентом; черновик плейбука с `SKILL.md`; «чистка» `hard_exit`.

## Что должно быть в вашем проекте

Раздел «Процесс» — как есть (если берёте OpenSpec). Раздел про код — 4–8 ошибок, которые реально случались в вашем проекте, по одной строке с причиной.

## Шаги адаптации

1. Раздел «Процесс» оставь.
2. Раздел про код перепиши: спроси пользователя «что новый разработчик или агент ломает чаще всего?», посмотри
   `git log` по фиксам и ревью-комментарии. Каждый пункт — **жирное имя.** + одно предложение.
3. Не дублируй доменные правила: в антипаттернах — коротко, подробности — в правиле области.
