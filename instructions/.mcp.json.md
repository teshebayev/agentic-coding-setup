# Инструкция агенту: `.mcp.json`

- **Что это:** проектный список MCP-серверов для Claude Code (коммитится)
- **Когда подхватывается:** при старте Claude Code в репозитории; на каждый новый сервер Claude Code спрашивает одобрение пользователя
- **Действие при переносе:** **заменить своим или удалить** — доменный файл нашего проекта, служит образцом формы

## Что в файле сейчас (проект «DWH-аналитик»)

Один сервер `dwh-analyst` — собственный MCP-сервер проекта (`uv run python -m dwh_analyst_mcp.server`) в
**demo**-профиле: SQLite `data/demo_dwh.sqlite`, демо-знание `dwh-analyst-mcp/demo/knowledge`. Через него Claude
Code при разработке плейбуков вызывает `search_schema`, `validate_sql`, `get_playbook`. Профиль живого DWH в
коммит не попадает. У автора сервер выключен в `.claude/settings.local.json`.

## Что должно быть в вашем проекте

Только серверы, которые помогают агенту разрабатывать и безопасны для коммита: read-only, на демо- или
dev-данных, без секретов в файле (секреты — `${VAR}` из окружения). Примеры: dev-база в режиме чтения,
документация фреймворка, собственный сервер проекта в тестовом профиле. Нет таких — файла не должно быть.

## Шаги адаптации

1. Удали `dwh-analyst`.
2. Спроси пользователя, какие MCP-серверы он уже использует для этого проекта и какие из них безопасно делить с
   командой. Боевые доступы — только в `.claude/settings.local.json` или `~/.claude.json`, не сюда.
3. Если серверов не осталось — удали файл и строку про MCP в `CLAUDE.md` и `docs/22-agentic-coding.md`.
4. Сервер, который ходит в живые данные, добавь в `ask`-список `scripts/agent/guard.sh` и `testing-runs.md`.
